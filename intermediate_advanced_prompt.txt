Prompt for Intermediate and Advanced Code Development

We are working on the Sari-Sari Store Simulator project for DSC 512. The project is a standalone three-level Python program that starts with a Basic one-day sales calculator, then expands into a one-month simulator with analytics, and finally becomes a five-year inventory optimization and pricing recommendation system .

We already created the Basic goal using this project structure:

The Basic code currently uses two input CSV files:

data/raw/inventory.csv
data/raw/transactions.csv

The inventory.csv file contains product-level information:

product_id
product_name
category
starting_stock
unit_cost
unit_price

The transactions.csv file contains sales activity:

transaction_id
transaction_date
product_id
quantity_sold

The Basic code reads those CSV files, validates them, joins transactions with inventory using product_id, calculates revenue, expense, gross profit, remaining stock, and saves output CSV files and SQLite tables.

Important design rules:

Do not overwrite data/raw/inventory.csv or data/raw/transactions.csv.
Treat files in data/raw/ as shared source data.

Save generated outputs to level-specific folders:

data/processed/basic/
data/processed/intermediate/
data/processed/advanced/

Use the same SQLite database:

src/database/sari_sari_store.db
Use SQLAlchemy to save DataFrames to SQLite.
Use SQL Magic only for notebook inspection/demo, not as the main program logic.
Keep all reusable logic in .py files, not only in Jupyter notebooks.
Use level-specific table names to avoid overwriting Basic results.

For example, Basic output tables should be named like:

basic_daily_transaction_details
basic_daily_product_summary
basic_daily_ledger_summary

Intermediate tables should use names like:

intermediate_monthly_transaction_details

Advanced tables should use names like:

A simple first version can use this logic:

gross_margin = (unit_price - unit_cost) / unit_price

If demand is high and gross margin is low:
    recommend a slight price increase.

If demand is low and stock is high:
    recommend a slight price decrease.

If competitor price is available:
    keep recommended price near competitor price.

Otherwise:
    recommended_price = current_price adjusted by demand trend.

Coding Style Requirements

Please follow the existing Basic code style:

Use clear function names.
Use pandas for CSV loading and calculations.
Use SQLAlchemy for SQLite output.
Use Path from pathlib for file paths.
Add docstrings to each function.
Keep raw data unchanged.
Save generated files to data/processed/<level>/.

Save database tables to:

src/database/sari_sari_store.db
Use if_exists="replace" only for generated level-specific output tables.
Avoid overwriting shared raw input files.
Return DataFrames from major functions so they can be tested or inspected in Jupyter.

After running the .py files, notebooks can inspect the SQLite database with SQL Magic:

%load_ext sql
